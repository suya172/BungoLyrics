# 仕様書：Bungo Lyric (青空文庫 歌詞ジェネレーター)
## 1. 概要
指定した青空文庫の作家の「語尾」「言葉遣い」「時代背景」「段落の区切り方」をLLMに深く分析させ、ユーザーが指定したテーマや追加指示に沿った歌詞を自動生成・ブラッシュアップできるWebアプリケーション。
## 2. 技術スタック
 * **Frontend / Backend:** Next.js (App Router, TypeScript)
 * **Styling:** Tailwind CSS, shadcn/ui
 * **LLM API:** Google Gen AI SDK (@google/genai)
   * **モデル:** gemini-2.5-pro（高度な文体模倣と、文脈追従性能を確保するため）
   * **生成方式:** 必ず generateContentStream を使用したストリーミング形式で返却すること（Vercelのタイムアウト対策およびUX向上のため）
 * **Data Source:** Aozora API（外部データソース）
 * **Deployment:** Vercel (GitHub連携による自動デプロイ)
## 3. 画面遷移・UI要件 (Single Page Application)
画面は1カラムの洗練されたモダンなUIとし、以下のセクションで構成する。また、どのメッセージにおいてもemojiの使用を禁じます。
### 3.1. 作家検索・選択セクション
 * 入力フォームに作家名を入力し「検索」ボタンを押下。
 * 検索結果をリスト表示し、ユーザーが作家を選択する。
### 3.2. 作品選択セクション
 * 選択された作家の著作一覧をAPIから取得し、チェックボックス付きのカード型リストで表示。
 * 各作品カードには「詳細（アコーディオン）」を設け、クリックすると作品の冒頭一部（約200文字）が表示される。
 * ユーザーは歌詞のベースとしたい作品を複数選択できる。
### 3.3. 歌詞生成・微調整セクション
 * **入力項目:**
   * 歌詞の「テーマ」（例: 都会の孤独、終わらない夏、未知への恐怖）または「テーマとする著作」（fetchしたものから1つ選択）
   * 「追加の要望（プロンプト微調整用）」テキストエリア（例: 「もっと明るいトーンにして」「サビに現代的なカタカナ語を混ぜて」など）
 * **生成ボタン:** 「この作家の文体で歌詞を生成」
 * **出力エリア:** 生成された歌詞をMarkdown形式で美しく表示。クリップボードへのコピー機能付き。
 * **リテイク機能:** 歌詞出力後、追加の要望を入力して「再生成」ボタンを押すと、これまでの会話文脈（セッション履歴）を維持したまま歌詞がブラッシュアップされる対話型UI。
### 3.4. ダイアログ・通知（例外処理）
 * **短すぎる場合の警告:** 選択された作品の合計文字数が極端に短い（合計500文字未満）場合、「選択されたテキストの量が少ないため、文体の再現度が低くなる可能性があります。このまま生成しますか？」という確認ダイアログ（Modal）を表示し、ユーザーが「続行」を押した場合のみ処理を進める。
### 3.5. ローディング画面（UX演出）
生成ボタン押下後、ストリーミングが開始されるまでの間、処理の進捗に合わせて以下のステップが順次ハイライトされるアニメーション（スケルトンや進捗バー付きのインジケーター）を表示する。
 1. ⏳ 「作品の本文データを取得中...」
 2. ⏳ 「[作家名]の言葉遣い・時代背景・段落構成を分析中...」
 3. ⏳ 「テーマ『[テーマ名]』に沿って歌詞を編纂中...」
 4. ✅ （ストリーミングが開始されたら、タイピング風に歌詞を1文字ずつ表示）
## 4. システムデータフロー & 処理要件
### 4.1. データソース (Aozora API) 連携仕様
フロントエンドと Next.js Route Handlers 間の通信、および外部APIとのデータ連携は、以下のインターフェース構造に準拠すること。
```typescript
// 1. 作家検索 (GET /api/authors?name=...)
type Artist = {
  id: number;       // 作家ID (例: 35)
  name: string;     // 作家名 (例: "太宰治")
};

// 2. 作品一覧取得 (GET /api/authors/{artist_id}/books)
type Book = {
  id: number;       // 作品ID (例: 2252)
  title: string;    // 作品名 (例: "走れメロス")
};

// 3. 本文取得 (GET /api/books/{book_id}/content)
type BookContent = {
  id: number;
  title: string;
  content: string;  // 青空文庫形式のテキスト（ルビや注記を含む生データ）
};

```
### 4.2. テキストクレンジングと制限（ロジック）
 * **クレンジング処理:** APIから取得した本文テキストから、青空文庫特有のルビや注記、外字情報を以下の正規表現を用いて確実に除去・整形した上でLLMに渡すこと。
```typescript
export function cleanAozoraText(rawText: string): string {
  if (!rawText) return "";
  let cleaned = rawText;
  cleaned = cleaned.replace(/《.*?》/g, ""); // ルビの削除
  cleaned = cleaned.replace(/［＃.*?］/g, ""); // 注記の削除
  cleaned = cleaned.replace(/〔.*?〕/g, "");   // 特殊符号の削除
  cleaned = cleaned.replace(/\n{3,}/g, "\n\n"); // 連続改行の集約
  return cleaned.trim();
}

```
 * **長すぎる場合の制限:** 選択された作品の合計文字数が **50,000文字** を超える場合、システムの破綻とAPIコスト・遅延を防ぐため、自動的に「先頭から50,000文字のみ」を切り出してLLMのコンテキストに追加する。
 * **データ取得の安全弁:** 本文のダウンロード時にFetchのタイムアウト（最大10秒）を設定し、応答がない場合はユーザーにトースト通知でエラーを表示すること。また、テキストパース時の文字コード（UTF-8）を明示的に指定すること。
### 4.3. LLMプロンプト構築（システムプロンプト要件）
Gemini APIに渡すシステム指示文には、以下の要素を厳格に含めること。
 * **文体模倣の指示:** 対象の作品群を分析し、単なる単語の模倣だけでなく、**「特有の語尾」「文章のリズム・言葉遣い」「その作家が生きた時代背景（レトロ感、思想）」「独特な段落の区切り方（改行のタイミング）」**を完全にトレースすること。
 * **歌詞フォーマットの指示:** J-POPや歌謡曲として歌える構造（Aメロ、Bメロ、サビ、アウトロなど）を明示的に持たせること。
 * **文脈の維持（リテイク時）:** ユーザーから微調整の指示が入った場合は、元の作家の文体特徴を失わないように配慮しながら、指示された要素だけをブレンドして書き直すこと。
## 5. デプロイ・環境変数要件 (Vercel)
 * APIキー等の機密情報は、フロントエンドに露出させずNext.jsのRoute Handlers（/api/generate など）経由で呼び出す。
 * 以下の環境変数を使用し、Vercelの管理画面から注入できる構成にする。
   * GEMINI_API_KEY (Google Gen AIのAPIキー)
   * AOZORA_API_URL (青空文庫データソースのベースURL)
